## Coverage Gaps and Quality Issues

### ⚠️ MISSING: SIG-012 — Editing a tab while a signature request is open does not cancel or alter the request

**Root cause:** The test `TestUpdateTab_SucceedsWithPendingRequest` (`backend/tests/models/tab_test.go:255`) semantically covers this rule — it creates a pending signature, edits the tab, and asserts the pending request retains its original `history_id` and `status`. However, the test is annotated with `// cinch:rule SIG-099`, which is a **dead marker** (no such rule exists). The checker reports SIG-012 as unmarked because no test carries that ID.

**Fix:** Replace `// cinch:rule SIG-099` with `// cinch:rule SIG-012` on `TestUpdateTab_SucceedsWithPendingRequest`.

### ⚠️ MISSING: TAB-003 — Every tab content save records new content into history, ordered newest-first

**Root cause:** The test `TestUpdateTab_MultipleEdits_HistoryOrderedByMostRecent` (`backend/tests/models/tab_test.go:226`) semantically covers this rule — it creates a tab, makes two edits, and asserts history has 2 entries ordered newest-first with the original content excluded (save-after semantics). The test has no `// cinch:rule` marker.

**Fix:** Add `// cinch:rule TAB-003` above `TestUpdateTab_MultipleEdits_HistoryOrderedByMostRecent`.

### ⚠️ QUALITY: SIG-002 — Test contradicts rule

The rule states: *"Multiple pending signature requests may exist per tab at a time — creating a request never conflicts with one already pending."*

The marked test `TestRequestSignature_AlreadyPending` (`backend/tests/handlers/tab_test.go:388`) asserts `http.StatusConflict` and `SIGNATURE_PENDING` when a second request is created on a tab that already has a pending request. This verifies the **opposite** of what the rule describes. Either the rule is aspirational (not yet implemented) or the test is incorrect.

### Dead marker: SIG-099

`// cinch:rule SIG-099` on `TestUpdateTab_SucceedsWithPendingRequest` (`backend/tests/models/tab_test.go:226`) does not resolve to any rule. This is the root cause of SIG-012 being reported as unmarked — the marker carries the wrong ID.
